Multimodal RAG System (Fully Local) – Project Requirements Document
Project Overview
Objective
Develop a fully local Multimodal Retrieval-Augmented Generation (RAG) System capable of understanding and answering questions from:
Text documents
Images
Tables
The entire solution must run offline using locally hosted models and local storage without any dependency on external APIs.
Key Constraints
All models must run locally.
Only GGUF-based LLMs are permitted.
No OpenAI, Claude, Gemini, Cohere, or other cloud APIs.
Retrieval, embedding generation, reranking, and evaluation must be executed locally.
The system should work on consumer-grade hardware.
Prioritize response speed and answer accuracy.

7. Evaluation Framework
Metric 1: Faithfulness
Question:
Does the answer contain only facts from retrieved context?
Target:
≥ 0.85

Metric 2: Answer Relevance
Question:
Does the answer address the user’s query?
Target:
≥ 0.80

Metric 3: Context Precision
Question:
How much retrieved context was actually useful?
Target:
≥ 0.75

Metric 4: Context Recall
Question:
Were all required chunks retrieved?
Target:
≥ 0.70

Metric 5: Answer Correctness
Question:
Is the final answer factually correct?
Target:
≥ 0.75

Metric 6: Latency
Target:
Metric
Goal
Query → First Token
< 3 sec
Full Response
< 20 sec

8. Running RAGAS Completely Offline
Normally:
RAGAS → OpenAI Judge
For this project:
RAGAS → Local Mistral Judge
Implementation:
Create LangChain wrapper around llama-cpp.
Pass wrapper into RAGAS.
Build evaluation dataset.
Run offline evaluation.
Note:
Scores will be noisier than GPT-4 evaluation but are reliable enough for comparing retrieval strategies.
